## Before you submit: the video rights

The built-in clips are copyrighted footage (Halo, Resident Evil, GTA: San Andreas, Crash Bandicoot, Star Wars Battlefront, and the PlayStation 2, GameCube, Xbox, and Dreamcast startups). The store's policies prohibit distributing content you don't have rights to, and the listing names those games. Google may reject the submission or take it down later after a copyright complaint. The options:

- Get permission from the rights holders.
- Ship only original or recreated loaders, and let people add their own clips through the library.
- Submit as is and accept the risk.

## Broad host permissions

On upload, the dashboard warns that the extension "may require an in-depth review" because of broad host permissions: the content script runs on every site. That's a delay, not a rejection, and the host permission justification below explains why it's needed. If reviews stay slow or it's rejected over this, [docs/opt-in-site-access.md](opt-in-site-access.md) is the plan for installing with no site access and letting users turn it on afterward.

In the meantime, anyone can install it without the store by loading it unpacked from a GitHub release (see the README's [Install without the Chrome Web Store](../README.md#install-without-the-chrome-web-store)).

## 1. Developer account (done)

Registered in the [Developer Dashboard](https://chrome.google.com/webstore/devconsole): 2-Step Verification on, the one-time $5 fee paid, publisher name and contact email set, and the trader or non-trader declaration filled in.

## 2. Upload package (done)

```sh
pnpm zip
```

This builds `loading-screenz.zip` (about 3 MB, 25 files) without the style guide or `.DS_Store` files. Version 1.1.0 was tested from the unzipped package: the popup and library pages load, all the built-in videos decode, and a link click plays the loading screen and then opens the link. The overlay also clears itself when a single-page app routes the link in-page, and when a link never loads a new page (like a download or an empty response).

For each later upload, bump `version` in `public/manifest.json` (and `package.json`) first.

## 4. Create the item and fill in the dashboard

Click **New item**, upload `loading-screenz.zip`, then fill in each tab.

### Store listing

**Summary** (from the manifest, up to 132 characters):

> Classic video game loading screens and console startups while you browse the web.

**Description:**

```text
Every click is a loading screen.

Remember staring at loading screens and console startups, waiting for the game to begin? Loading Screenz brings them back. When you click a link, a classic loading screen plays for a few seconds before the next page opens.

9 LEGENDARY SCREENS BUILT IN
Game loading screens: Halo, Resident Evil, GTA: San Andreas, Crash Bandicoot, and Star Wars Battlefront.
Console startups: PlayStation 2, GameCube, Xbox, and Dreamcast.

TOTAL CONTROL FROM THE TOOLBAR

Loading screens only play for normal links that open in the same tab. Links opened in new tabs, downloads, and in-app navigation on sites like YouTube are left alone.

Not affiliated with or endorsed by Microsoft, Sony, Nintendo, Sega, Capcom, Rockstar Games, or Activision. All trademarks are the property of their respective owners.
```

### Privacy practices

**Single purpose:**

```text
Shows a short classic video game loading screen video before a clicked link opens.
```

**`storage` justification:**

```text
Saves the user's settings: whether the extension is on, which loading screen to show, how often (frequency), how long (duration), and which screens are in the random rotation.
```

**`unlimitedStorage` justification:**

```text
Users can add their own video files to a personal library, stored locally in the extension's IndexedDB. These videos can exceed the default storage quota. Nothing is uploaded.
```

**Host permission justification** (the content script matches `http://*/*` and `https://*/*`):

```text
The extension shows its loading screen when the user clicks a link on any website, so its content script needs to run on every site. It only looks at the link that was clicked, reads nothing else from the page, and sends no data anywhere.
```

**Remote code:** No, I am not using remote code. Everything is bundled in the package.

**Data usage:** don't check any of the data types (the extension collects none), then check all three certifications: no selling or transferring data to third parties, no use unrelated to the single purpose, and no use for creditworthiness or lending.

**Privacy policy URL:** https://www.loadingscreenz.com/privacy

### Distribution

- **Payments:** Free
- **Visibility:** Public, or Unlisted to soft-launch with only people who have the link
- **Regions:** All regions

## 5. Submit for review

1. Click **Submit for review**. Choose whether to publish automatically on approval or manually afterward.
2. Review usually takes a few days. Extensions that run on all sites often get a longer review, sometimes a week or two.
3. If it's rejected, the email names the policy. Fix it, upload a new version if needed, and resubmit.
4. Once approved, the listing URL looks like `https://chromewebstore.google.com/detail/loading-screenz/<extension-id>`.

## 6. After it's live

1. In the Vercel project, set `NEXT_PUBLIC_INSTALL_URL` to the store URL and redeploy. Every Install button on the site switches over.
2. Update the README's Install section to link to the store.
3. For updates, bump the version, run `pnpm zip`, and upload the new package in the dashboard. Every update is reviewed again.

The same zip also works for [Microsoft Edge Add-ons](https://partner.microsoft.com/dashboard/microsoftedge), which is free and has a similar form.
